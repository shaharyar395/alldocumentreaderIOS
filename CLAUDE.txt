What it is
A document reader: splash, first-launch language, 3-page onboarding, then a 3-tab home (All files, Tools, Settings).
In-app viewers and editors for PDF, Word, Excel, PowerPoint, TXT, and images.
Create, convert, scan, PDF edit/pages/merge/split, 16 crowned templates, Premium, ads, FAQ, feedback, explore.
Privacy policy: https://sites.google.com/view/mob-apps-inc/privacy-policy
Do not invent a support email.

Launch
First launch: Splash -> Language -> Onboarding -> Home.
Later: Splash -> App Open ad if not Premium -> last tab.
Welcome back after the app was in the background about 3 seconds, then an App Open ad.
Do not show welcome-back after the file picker, share sheet, or an incoming file (ResumeGuard).
Theme: System / Light / Dark, instant, no black flash. Splash stays light #F7F8FC. Dark scaffold #10141C.
themeAnimationDuration is Duration.zero. Portrait-first. The reader may rotate; do not lock the Android activity to portrait in the manifest.

State
AppSettings and FileLibrary are ChangeNotifiers held by AppScope (InheritedWidget).
MaterialApp is a child so setState does not reset the Navigator.
Do not call notifyListeners from outside FileLibrary (use setStorage).
Do not use AppScope.of in initState. Use didChangeDependencies or a post-frame callback.
setFlag uses if/else so flags stay independent: coachSeen, discoverSeen, horizontalHintSeen, pageTipSeen, mergePromptShown, markupTipSeen.

Files
Android: real files are used IN PLACE (DocEntry.relativePath is the absolute path; DocEntry.fullPath).
App outputs go to public Documents/AllDocumentReader/<import|convert|create|merged|split> (private
library/<folder> only as a fallback when that folder is not writable).
iOS: outputs and imports in Documents/library/<folder> (visible in Files: UIFileSharingEnabled +
LSSupportsOpeningDocumentsInPlace); files in Documents are listed in place; paths are stored relative to
Documents/library because the iOS container path changes on updates.
Older versions' private copies in Documents/library/<folder> stay listed (relative paths).
Index and lists: <ApplicationSupport>/library_meta/index.json + state.json (recent, bookmarks, "new",
known paths). Recycle bin: <ApplicationSupport>/RecycleBin, 30 days, restore to the original path.
Unique names are "stem (n).ext".
FileLibrary.memory() is for tests. In memory mode, rescan returns after scan().
Open-in uses MethodChannel com.theoccess.alldocreader/platform.
Android opens incoming content:// URIs in place when they map to a readable path, else copies them into
Documents/AllDocumentReader/import (same name+size reused). iOS copies "Open in" URLs into
Documents/library/import (same name+size reused, "name (n).ext", extension from the type when missing).

Device scan
MANAGE_EXTERNAL_STORAGE IS declared (decision of the parity round, same as the native Android app).
Android access = Environment.isExternalStorageManager() (11+) / READ_EXTERNAL_STORAGE (10 and older).
Allow -> ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION (11+) / runtime READ+WRITE dialog (10 and older).
No permission prompt at splash / language / onboarding: the custom dialog shows once on the All files tab.
Scan (MainActivity.scanDevice): MediaStore.Files DATA LIKE '%.ext' for every extension + folder walk from
/storage/emulated/0, 8 levels, no dot names, top-level Android/ skipped except Android/media. No size or
count limit. ContentObserver -> "onMediaChanged" (2.5 s debounce); rescan on resume when older than 8 s.
More than 300 new files in one scan are not tagged "New". Without access only the app's own outputs.
iOS: FilePicker getDirectoryPath stored in prefs key ios_scan_root (copied in once, not again after
delete/rename), plus a security-scoped bookmark. Memory mode returns first.

PDF and Office
PDF create uses package:pdf. Hide PdfDocument from package:pdf/pdf.dart because pdfx also exports it.
Viewing uses pdfx PdfViewPinch. Text extraction is lib/services/pdf_text.dart.
rewritePdf in lib/services/pdf_rewrite.dart appends an incremental classic xref.
It supports classic xref and xref streams, expands type-2 object streams, and scans objects if xref parse fails.
Text edits, vector marks, and JPEG image stamps stay in the text layer. Raster bake is only if rewritePdf returns null.
Office uses archive + xml. Word and PowerPoint rendering is richer than plain text (headers, footers, styles, numbering, text boxes, columns, slide tables) but it is not Microsoft's layout engine.
OCR: ML Kit scripts latin, chinese, devanagiri, japanese, korean. Arabic, Persian, Urdu, and Thai use Tesseract (assets/tessdata). OCR only pages whose text layer is empty.

Android build notes that already bit us
minSdk 24. Release is signed with the debug keystore, so the APK installs on a device and is not Play-upload-ready.
MainActivity extends FlutterFragmentActivity so the storage-tree picker can use registerForActivityResult.
LaunchTheme and NormalTheme must parent Theme.AppCompat.Light.NoActionBar. A platform theme crashes on launch.
ML Kit language packs are implementation dependencies in android/app/build.gradle.kts (chinese, devanagari, japanese, korean 16.0.1).
Library modules are forced to compileSdk 36 in android/build.gradle.kts.
Tesseract is com.googlecode via JitPack: cz.adaptech.tesseract4android:tesseract4android:4.9.0
(the plugin's local AAR cannot be packaged by current AGP). JitPack is in android/build.gradle.kts.
Two pub-cache Gradle patches are NOT in git and are lost on a clean pub get:
  flutter_tesseract_ocr 0.4.31 android/build.gradle (no jcenter, Maven Tesseract dependency)
  google_mobile_ads 5.3.1 android/build.gradle (configurations instead of configurations.all)
R8 full mode is off (android.enableR8.fullMode=false). android/app/proguard-rules.pro keeps WorkManager/Room.
Without that, release builds crash at startup: Failed to create an instance of androidx.work.impl.WorkDatabase.
AGP 9.1.0, Kotlin 2.4.0, Gradle 9.3.1. android.newDsl=false and android.builtInKotlin=false.

APK size (keep these; the release APK is 37.9 MB and installs on the phones)
- Do not go back to a fat APK. The 130.5 MB build packed three CPU copies (arm64, armeabi-v7a, x86_64)
  uncompressed, plus the bundled ML Kit Latin recognizer (libmlkit_google_ocr_pipeline.so and model assets).
- android/app/build.gradle.kts: ndk.abiFilters is armeabi-v7a and arm64-v8a only. Clear the list Flutter's
  plugin fills in before that block. Keep x86 and x86_64 out. packaging.jniLibs.useLegacyPackaging = true
  so the .so files are compressed in the APK. The excludes drop lib/x86 and lib/x86_64.
- The Samsung A13 (SM-A135F) is 32-bit only: ro.product.cpu.abi = armeabi-v7a. An arm64-only APK installs
  as "app isn't compatible with your phone". Keep armeabi-v7a. Keep arm64-v8a for 64-bit phones.
- android/build.gradle.kts substitutes com.google.mlkit:text-recognition (and chinese, devanagari, japanese,
  korean) with the Play services unbundled artifacts. Latin / Chinese / Japanese / Korean / Devanagari OCR
  downloads its model on first use. Arabic, Persian, Urdu, and Thai stay offline via assets/tessdata and
  Tesseract. Do not put the bundled ML Kit recognizer back in.
- Release build: flutter build apk --release --target-platform android-arm,android-arm64
- It will not match the native app's 23 MB. libflutter + libapp are the Flutter engine and compiled Dart.
